# TagQuest

NFCタグをゲームカートリッジとして使う、超小容量のブラウザRPG。
開発方針・要件は [project.md](./project.md) を参照してください。

## 技術構成

- `web/`: TypeScript + Vite + HTML/CSS + Canvas 2D + Tailwind CSS / daisyUI
- `compiler/`: Pythonによる城・街の容量検証用コンパイラ
- バックエンド・データベースは使用しません。ReactなどのJavaScript UIフレームワークは導入せず、画面のUIにはdaisyUIを使用します。

## 開発環境

- Node.js 24系 + npm（`.nvmrc` に指定）
- Python 3.12以上（マップの生成に使用。外部パッケージは不要）

## Webの起動

```sh
cd web
npm ci
npm run dev
```

ブラウザで http://localhost:5173/ を開きます。
画面上部に歩行見本と文字の見本があり、続いて街並みと各素材のプレビューを表示します。daisyUIのカードとボタンを使い、上部のカテゴリボタンで素材へ移動できます。「ダーク／レトロ」で配色を切り替えられます（再読み込みするとダークに戻ります）。
「歩いてみる」で城・街を選び、「プレイ」を押すと歩行を試せます。矢印キー・WASD・画面の方向ボタンで1マスずつ移動します。入力はプレイ画面にフォーカスがある間だけ受け付けます。
初期画面で城の床のドット絵を確認できます。「石 → 赤 → 赤 → 赤 → 石」（左右に大理石1マスずつ、中央に赤いカーペット3マス）の横並びと、縦に敷き詰めた表示を用意しています。
奥と左右の壁で囲み、玉座・左右の柱を置いた部屋の表示と、玉座・壁・柱それぞれの拡大表示も確認できます。
ポートが使用中の場合は、起動時にエラーを表示します。

## 型チェック・ビルド

`web/` で実行します。

```sh
npm run typecheck
npm run build
npm run preview
```

`build` は型チェック後に静的ファイルを `web/dist/` へ出力します。
`preview` はビルド結果を http://localhost:4173/ で確認するためのコマンドです。

Viteの使い方は [公式ガイド](https://vite.dev/guide/) を参照してください。

## 現在の段階

画面UIはTailwind CSS 4とdaisyUI 5で構成しています。`web/vite.config.ts` でTailwindのViteプラグインを有効にし、`web/src/style.css` で使用するdaisyUIコンポーネントと `night`・`retro` テーマを指定しています。ドット絵の配置・拡大サイズ・Canvas描画は既存のまま、画面のカードと配色を共通化しています。表示する文言はタイトル・素材名・操作名に絞り、説明文や英語のカテゴリラベル、更新内容の通知は表示しません。エラー時のみ通知します。配色切り替えはdaisyUIのCSSによるテーマ切り替えを使い、ゲーム状態の保存は行いません。

ゲーム内向けの文字にはPixelMplus12を採用しています。`web/src/assets/fonts/` に未改変のフォント・ライセンス・出典を同梱し、`.game-ui` と歩行プレビューの `.play-session` に適用します。画面上部の「文字の見本」で、会話・コマンド・HP／MP・ゴールドを24px（元の12pxの2倍）で表示します。通常の画面UIはシステムフォントです。見本は静的な表示確認用で、数値や会話はゲームデータではありません。

開発環境と、堀・橋付きの城の外観、武器屋・防具屋・道具屋と店員、街の住民3人、入れない民家2種類、井戸と光る落とし物、街の床3種類・城の床2種類・壁・玉座・柱・プレイヤー・王様のCanvasプレビューまで用意しています。
文字の見本に続いて、街から見た城の外観を表示します。`web/src/data/objects/castle-exterior.ts` に80×64ドットの石造りの城、`web/src/data/tiles/castle-moat.ts` と `castle-bridge.ts` に各16×16ドットの水面・木橋を保存しています。城は既存の壁と石材の色を共有し、左右の塔と中央の城門を配置しています。`compiler/maps/town.json` に床と配置を保存し、`web/src/renderer/compiled-scene.ts` がバイナリから復元した13×31マスの街を描きます。城を堀で囲み、入口の木橋を街のレンガ道につなぎ、手前に3軒の店と2軒の民家、住民3人を置きます。外観プレビューに加え、「歩いてみる」で通行判定を確認できます。城門前と城の下端の出口で行き来できます。
武器屋と防具屋は、参考画像に合わせて屋根のない見下ろしの売り場にしています。`web/src/data/objects/town-shops.ts` に各80×80ドットの売り場とカウンターを別レイヤーで保存しています。石積みの奥壁、紫系のタイル床、木箱と商品棚があり、武器屋は剣・斧・槍、防具屋は盾・胸当て・兜を飾っています。店員は `web/src/data/characters/shopkeepers.ts` に各32×32ドットで別素材として保存し、カウンターの奥に正面向きで配置しています。単独表示は `web/src/renderer/shop-preview.ts`、街は `compiled-scene.ts` で売り場・店員・カウンターの順に重ね、同じ構図を描きます。カウンター越しに店員へ話しかけられます。商品と価格は共通JSONから設定し、挨拶の後に購入・売却できます。
道具屋も `web/src/data/objects/town-shops.ts` の80×80ドットの売り場を共有し、薬瓶の看板、赤と緑の瓶・薬草・包みを並べています。緑の服の店員は `shopkeepers.ts` の別素材です。回復アイテムを扱う店として街の手前に配置しています。棚の品は外観用で、実際の商品IDは `shop-catalog.json` に設定します。Web共通一覧 `web/src/data/item-catalog.json` にやくそう・どくけしそう・まほうの水の効果・価格を設定し、購入・売却・使用に対応しています。
街の住民は `web/src/data/characters/town-npcs.ts` に各32×32ドットで保存しています。緑の服と革鞄の若者、紫の服と髪飾りの女性、灰色の髪と木の杖を持つおじいさんの3種類です。街の道沿いと単独の素材一覧で表示します。現在は正面の静止画で、テンプレート／自由文の会話とバイナリでのNPC配置に対応しています。NPCの自動歩行は未実装です。
民家は `web/src/data/objects/town-houses.ts` に各64×64ドットで保存しています。赤茶と青灰の瓦屋根、煙突、小窓、閉じた板戸がある外観で、赤茶の家には窓辺の花箱も付けています。お店より手前の道沿いと素材一覧に表示します。定義には `enterable: false` と `blocksMovement: true` を持たせ、入れない建物として扱う方針です。歩行プレビューでは中央2×4マスの配置枠を障害物として扱い、絵の左右のはみ出しは通行できます。家の中への移動は未実装です。
井戸は `web/src/data/objects/well.ts` に32×40ドットで保存しています。石の縁と水面、木の支柱、滑車・縄・桶を描き、街の道沿いの石敷きに配置しています。落とし物の光は `web/src/data/effects/loot-sparkle.ts` の16×16ドット・8コマの素材で、`web/src/renderer/loot-preview.ts` が約1.28秒周期で繰り返します。街の背景とは別の透過Canvasに光だけを重ね、素材一覧にも草の上で表示します。動きを減らす端末設定では静止画に切り替えます。キラキラへアイテムIDを設定すると、接触または正面から調べて1個取得でき、そのプレイ中は光が消えます。井戸にもエディタで調べたときのメッセージやアイテムを設定できます。
街の床は `web/src/data/tiles/town-grass.ts`（草）、`town-dirt.ts`（土）、`town-brick.ts`（灰色系のレンガ）に16×16ドットで保存しています。いずれも歩ける床として扱います。お店・民家・井戸と落とし物の素材一覧の下に各素材の拡大表示と、草地にレンガの十字路・広場、道の脇に土を並べた11×11マスのプレビューがあります。配置例は `web/src/renderer/town-preview.ts` に分離しており、実際のゲーム用マップではありません。
城の床は大理石の床と赤いカーペットの2種類で、どちらも歩けるマスとして扱います。
仮の16×16ドットで、`web/src/data/tiles/castle-floor.ts` が大理石の床、`web/src/data/tiles/castle-carpet.ts` が赤いカーペットの色と模様です。
玉座は `web/src/data/objects/throne.ts` に16×16ドットで保存しています。数字が色番号、`.` が透過部分で、床の上に重ね描きします。オブジェクトは床と別の幅・高さを持てます。
壁は `web/src/data/tiles/castle-wall.ts` に16×16ドット、柱は `web/src/data/objects/pillar.ts` に16×24ドットで保存しています。
左右の壁は `web/src/data/tiles/castle-side-wall.ts`、左上・右上の角は `web/src/data/tiles/castle-wall-corner.ts` に保存しています。
エディタの壁は「城の壁」「魔王城の壁」「岩の壁」の各1種類です。城・魔王城の壁は周囲8マスの壁と床から上・下・左右・角の向きが自動で変わります。見た目のパーツはWeb側に保存し、JSONとNFCには素材ごとに1種類のIDを保存します。旧方向名／IDも読み込めます。共通の石積みと明暗は維持し、描画から当たり判定へ影響しません。詳細と見本は [自動の壁](./art/walls/README.md) を参照してください。
プレイヤーは画像生成で制作した黒髪・青い服・赤いマントの勇者です。`web/src/assets/player/` に正面・背面・左右それぞれ64×64の透過PNGと、2×2に並べた `hero-sheet-64.png` を保存しています。`web/src/data/characters/player.ts` で読み込み、髪や服の陰影を整理してドット感を強めました。城での人物の表示枠は32×32です。城を448px幅で表示し、64×64の人物素材を素材一覧と同じ128px幅（1ドット2px）で確認できます。Canvasの描画解像度は8倍にして、人物素材を整数倍で描画し、ドット幅のムラを抑えます。部屋は112×96の論理サイズで、主人公の背面と正面を別々の城プレビューで見比べられます。狭い画面では横スクロールして、城の自動縮小を避けます。各方向の素材も単独で確認できます。
現在の生成原画像は `art/player/hero-chunky-generated.png`、使用した編集プロンプトと縮小方法は [ドット感の調整記録](./art/player/chunky-generation.md) に保存しています。以前の素材と [初回の生成記録](./art/player/generation.md) も残しています。
並べた表示は素材確認用です。現在の配置は容量検証用の城・街のJSONに保存しています。本番マップは未確定です。
主人公の正面は `player.ts` の `pixelCorrections` で、向かって右の太い眉の4ドットを肌色に戻し、右の黒目を左と同じ横1×縦2ドット、隣の白目を1列に整えています。左眉は髪と重なる両端を描かず、前髪の隙間に見える中央1ドットだけ追加しています。元のPNGを保持し、素材一覧と城の表示に共通で反映します。左の目・前髪・衣装・他の方向は変更していません。

王様は `web/src/assets/king/` に正面の立ち姿・玉座込みの座り姿の `king-sheet-64.png` と、椅子を含まない `king-seated-overlay-64.png` を保存しています。これらは各64×64の透過PNGです。勇者をベースにした `king-standing-hero-style-64.png`（64×64）は王の3点セット装備中の主人公の正面姿に使用し、城のNPCには元の年配の王様（`king-sheet-64.png` の左の立ち姿）を使用しています。粗いドット版の `king-standing-chunky-48.png`（48×48）も以前の試作として残しています。城では前に作った `throne.ts` を1.5倍にして奥に置き、その手前に年配の王様を32×32の表示枠で配置しています。勇者は王様と重ならないよう、さらに手前に配置しています。以前の立ち絵と座り姿を保存し、装備中の左右・後ろ姿も素材一覧で確認できます。原画像と使用プロンプトは [王様の生成記録](./art/king/generation.md) 、[重ね描き用の生成記録](./art/king/overlay-generation.md)、[粗いドット版の生成記録](./art/king/chunky-standing-generation.md)、[勇者をベースにした生成記録](./art/king/hero-style-generation.md) を参照してください。
Pythonが生成した試作バイナリの読み込みと描画に対応しています。プレイヤー移動・当たり判定は紹介画面とエディタで試せます。URL FragmentのBase64urlからゲームを直接起動できます。紹介・エディタ・ゲームは必要な画面だけを読み込みます。
王様はステージごとの設定で有効・無効と出現率を指定し、歩行中に遭遇します。倒した場合にだけマップの表示・会話・当たり判定から消え、同じプレイ中の再訪でも戻りません。現在の王様は逃走不可です。逃走を許可する設定にした場合は、逃げても残り、再遭遇できます。勝利報酬は敵一覧JSONの `reward` から設定し、勝利時だけ一度付与します。王様の報酬は王の王冠・王のローブ・王の杖・王の剣を各1個、1,500G、900EXPです。敵のターン・HP・攻撃力・防御力・セリフと行動パターンはJSONから設定できます。[戦闘configの編集方法](./web/src/data/encounters/README.md) と `project.md` 第45節を参照してください。

## 城と街の容量検証

`compiler/maps/castle.json` と `town.json` の床・オブジェクト・NPC・演出をバイナリにしています。
Web側は `web/src/data/generated/scenes.bin` を読み込み、現在の見た目を復元します。
`web/` で `npm run dev` と `npm run build` を実行すると、開始時にマップも自動生成します。
起動中にJSONを編集した場合は `npm run compile:maps` で再生成します。

| 項目 | バイト数 |
|---|---:|
| 城7×6 | 51B |
| 街13×31 | 151B |
| 共通ヘッダー | 4B |
| 合計 | 202B |

床をRAWで詰めた場合の合計365Bに対して、RECTで202Bになりました。
Base64urlは275文字、仮の `https://example.com/g#` を含むURLは297Bです。
生成URLからゲームを起動できます。単一NDEF/TLV込みの使用量は302Bです。実タグ書き込みは未検証です。
初期目標300Bまで残り94Bですが、他3マップ・商品や報酬などは未収録です。
今回の形式は容量確認のための試作で、最終仕様ではありません。

生成手順と検証コマンドは [compiler/README.md](./compiler/README.md)、形式は [compiler/FORMAT.md](./compiler/FORMAT.md)、実測の詳細は `web/src/data/generated/scenes.report.json` を参照してください。
見本の容量には王様・街のNPC6人のテンプレート会話と、キラキラ2件のアイテムID、城と街の出口2件、城のエンカウント設定を含みます。自由文を増やすとUTF-8本文長に応じて容量が増えます。

## ワールドエディタ

開発サーバーの [ワールドエディタ](http://localhost:5173/#editor) を開きます。素材一覧の上部からも移動できます。
元の城7×6・街13×31を初期配置として、マップを追加し、各マップのサイズを1〜32マスで変更できます。
新しいマップは草の16×16マスです。この上限は現在の試作バイナリ形式に合わせたもので、最終的なフィールド規模は未確定です。

- 「床・壁」から素材を選び、ペンでドラッグ、または四角塗りで範囲を塗ります。
- 「空白」は床を描かない透明なマスです。ペン・四角塗りで床を消せます。NPCや建物は別の配置として残ります。素材ボタンの市松模様は透明部分の目印です。
- 建物・家具、NPC、装飾を選んでクリックすると配置できます。「選択・移動」でドラッグ、右側の一覧で選択・座標編集・削除もできます。
- 配置は1マスまたは2px刻み。開始位置とステージごとのエンカウントも編集できます。
- 主人公の配置枠は横1×縦2マス、移動時の当たり判定は下側の足元1×1マスです。頭と左右にはみ出す絵は判定しません。絵は32×32pxのまま中央に描き、左右8pxずつはみ出します。「開始位置」で設置し、「選択・移動」で枠をドラッグできます。右側の主人公の「選択」から座標入力もできます。選択中は足元の当たり判定を緑の点線で表示します。
- NPC全9種類（王様・店員3人・住民3人・洞窟の魔女・森の妖精）は横1×縦2マスの配置枠と、下側1×1マスの当たり判定です。絵は32×32pxのまま中央に描き、左右8pxずつはみ出します。選択・移動・座標入力は配置枠を使い、選択中は足元を緑の点線で表示します。頭の後ろを通れ、会話も足元を基準にします。建物・木・NPC・宝箱は通行判定の下端で描画順を決め、主人公が奥にいると隠れ、手前なら上に描かれます。同じ奥行きでは主人公を手前にします。
- 玉座の編集枠は3×2マス、当たり判定は中央の1×2マス。柱は1×2、井戸は2×3マス。素材一覧・城の絵は維持し、エディタの選択・移動・入力座標を配置枠にそろえています。素材のボタンにも配置枠のマス数を表示します。
- 保存済みの配置が半端な位置にある場合は「配置をマスにそろえる」で調整できます。石縁は細かな形状を維持するため対象外です。この操作も「戻す」に対応しています。
- サイズ変更で範囲外になった床・配置物は取り除きます。「戻す／やり直す」（⌘/Ctrl+Z、Shift付きでやり直し）で復元できます。
- 「全マップを削除」は確認してから、現在の全マップと床・配置物・会話・出口・エンカウント設定をまとめて消します。16×16の「空のマップ」1枚から編集を再開できます。結果はブラウザに自動保存され、同じ編集セッションの「戻す／やり直す」に対応します。
- 新規配置・移動は枠全体がマップに収まる範囲に制限します。縮小時は残った配置枠を内側に寄せ、入り切らないサイズの配置物は取り除きます。
- 全マップのバイナリ容量、マップごとの床・配置の容量をリアルタイムに表示します。300Bは試作の目標で、URLのアドレス・NDEFの容量は別です。
- 「▶ プレイ」で編集中のマップを試せます。書き出しと同じバイナリを復号し、設定した開始位置から矢印キー・WASD・画面の方向ボタンで移動します。「最初から」で開始位置に戻り、「編集に戻る」で編集を再開します。プレイ中の位置・向きは一時的な状態で、マップJSON・ブラウザ保存・取り消し履歴は変更しません。
- 大理石・カーペット・草・土・レンガ・橋は通行可能、壁・空白・水は通行不可です。主人公の足元1×1マスが建物・家具・NPCの当たり判定に重なると止まります。木とNPCは足元だけが通行を妨げます。主人公の頭と絵の左右のはみ出しは判定に含めず、キラキラと堀の石縁は通行を妨げません。開始位置の足元が通行不可の場所に重なる場合は、プレイ前にエラーを表示します。

編集内容は同じブラウザ・同じオリジンのlocalStorageに自動保存します。JSON書き出しでファイルにも保存できます。
「マップJSON」は選択中の1マップ、「ワールドJSON」は全マップ、「バイナリ」はTQ v8／v9形式です。洞窟などID 16以降の床を使う場合はv9、それ以外はv8を出力します。
新しいJSONの開始座標と全NPCの座標は配置枠の左上（`spawnAnchor: "frame"`、`npcAnchor: "frame"`）です。住民用の旧識別値 `residentAnchor: "frame"` も併記します。従来のブラウザ保存・JSON・TQ v1〜v7バイナリも描画位置を保って読み込めます。会話・アイテム指定のない旧データも読み込めます。現在の見本の城と街は合計202Bです。
「JSONを開く」は単体マップJSON・配列・ワールドJSONを読み込み、現在の編集全体を置き換えます。「戻す」で復元できます。
エディタの編集は素材一覧やリポジトリ内のJSONを直接変更しません。商品購入・売却・装備・アイテム使用・戦闘の数値計算に対応し、NFC実機書き込みは未対応です。
紹介画面とエディタは同じ歩行処理・描画処理を使います。紹介画面の街は見本用の仮の開始位置 `(96,464)` で試せますが、元の街の開始位置は未設定のままです。エディタでは各マップに「開始位置」を置いてください。

検証は `web/` で `npm run verify:editor`・`npm run verify:walls`・`npm run verify:interactions`・`npm run verify:world`・`npm run verify:encounters`・`npm run verify:battle`・`npm run verify:economy`・`npm run verify:progression`。編集操作のDOMテスト、戦闘のターンと状態、成長と習得・装備条件、ブラウザ側のエンコーダー・Pythonコンパイラ・TypeScriptデコーダーの一致を確認します。ブラウザ実画面の目視確認は未実施です。

## 会話・キラキラの取得

紹介画面の「歩いてみる」とエディタの「プレイ」で、正面のNPCにE・Enter・Spaceまたは「はなす・しらべる」で話しかけられます。店員はカウンター越しに対応し、会話中は移動を止めます。同じ決定操作でメッセージを閉じます。

エディタでNPCを選択し、「会話」をテンプレートまたは自由文へ切り替え、「配置を反映」で保存します。自由文はUTF-8で1024B以内です。キラキラを選ぶと「アイテム」から中身を指定できます。既存のブラウザ保存に設定がなければ未設定のままなので、この欄で追加してください。

宝箱は「建物・家具」、洞窟の魔女・森の妖精は「NPC」から置けます。宝箱は16×16px・1×1マス、魔女と妖精は32×32pxのドット素材です。魔女・妖精の会話テンプレートはID 7・8を追加し、既存テンプレートのIDを維持しています。会話と宝箱の中身は編集して指定し、見本の森・洞窟へは自動配置しません。

宝箱は隣接して向き合い、「はなす・しらべる」で開きます。設定したメッセージとアイテム取得文を表示し、同じプレイ中にアイテムを一度だけ受け取れます。空箱・開いた箱は「宝箱は空っぽだった。」と表示します。開いた絵と通行判定は残り、ステージを往復しても開いたままです。「最初から」で初期化します。開封状態はプレイ中の状態で、編集JSONやNFCの配置データを変更しません。原寸素材と4倍の一覧は `art/adventure-materials/`、再出力は `web/` で `npm run export:adventure-materials` です。

玉座・柱・井戸・城・各お店・民家にも、選択すると「調べたときのメッセージ」と「アイテム」の設定が出ます。どちらか一方でも両方でも設定できます。「配置を反映」で保存し、プレイ中に調べると本文→「○○を手に入れた！」の順に表示します。アイテムは1プレイ中に1回だけ、オブジェクトは取得後も残ります。再び調べると設定した本文を表示し、アイテムを重複取得しません。テンプレートはNPCと共通です。NFC用バイナリと容量計算にも設定を含め、「最初から」で取得済み状態を初期化します。

Web側の一覧は仮に0＝やくそう、1＝どくけしそう、2＝まほうの水。NFC向けバイナリには名前を重複保存せずIDを入れます。会話もWeb共通テンプレートのIDまたは自由文を保存します。

取得時は「やくそうを手に入れた！」のように表示し、「どうぐ」で所持数を確認できます。取得済みのキラキラはそのプレイ中だけ消えます。「最初から」で所持品・取得状態をリセットし、編集マップやブラウザ保存へプレイ結果は書き戻しません。使用効果・価格・装備・売買は共通JSONから設定します。プレイ結果の永続セーブはproject.md第13節の方針に従い追加しません。


スマホ向けのプレイではマップと操作を同じ枠にまとめています。会話・どうぐはゲーム枠内のウィンドウに表示し、操作欄の位置を保ちます。方向ボタンは長押し移動に対応し、「どうぐ」は「とじる」で戻ります。所持品表示中も移動を止めます。小さな城は画面幅に合わせた整数倍率、街は追従カメラで表示し、横向きで高さが低い画面では操作を右側に置きます。


## ステージ間の移動

紹介画面では、城の下端のカーペット中央から下へ進むと街の橋へ出ます。橋から上へ進んで城門前へ入ると城へ戻ります。画面内のステージ名とカメラを切り替え、移動直後の長押し入力を解除します。

エディタは「出口」でマップをタップして追加し、「出口・ステージ移動」の欄で移動先・到着する足元の列／行・向きを指定して「出口を反映」を押します。列と行は画面上では1始まりです。到着先の開始位置は未設定でも構いません。往復させる場合は両方のマップに出口を置いてください。壁・水・建物などに出口や到着マスが重なる場合、プレイ開始時にエラーを表示します。

ステージを移っても、拾ったアイテムと各マップの取得済みキラキラは保持します。「最初から」で開始マップ・所持品・取得状態をリセットします。編集データやNFCへプレイ結果は書き戻しません。保存済みの旧マップに出口がない場合は、この欄で追加してください。接続を保つ保存・読み込みにはワールドJSONを使います。


## 歩いているときのエンカウント

指定ステージで1マス移動できるたびに、設定した確率で敵が出現します。見本の城は仮に1歩10%、街は抽選なしです。壁への足踏み・会話・所持品表示・待機では抽選せず、出口ではステージ移動を優先します。

エディタの「エンカウント」で「出現する敵」・有効／無効・1歩ごとの確率（0〜100%）を設定し、「エンカウントを反映」を押します。王様と草原・森向けのモンスター3種類を選べます。100%にすると動作確認しやすくなります。旧保存マップには自動で追加せず、設定なしは抽選なしのままです。

王様と遭遇すると城内背景の戦闘画面に切り替わり、元の王様の立ち絵を中央に大きく表示します。下部に「たたかう・どうぐ・ぼうぎょ・にげる」と主人公HPを置き、タップまたは矢印／WASDとE・Enter・Spaceで選択します。「たたかう」から王様の名前／姿をタップすると攻撃、「つづける」で敵のターン、さらに「つづける」で次のコマンドへ進みます。「ぼうぎょ」は直後の敵ターンのダメージを半減します。「どうぐ」は所持品確認です。逃走可能な敵は「にげる」→「フィールドに戻る」で歩行を再開します。王様・魔王は逃走不可で、「にげる」を選ぶと警告を表示してコマンド選択に留まります。ターンは消費しません。対象・所持品・逃走の取り消しはEscape。確定した行動・敵ターン・勝敗は取り消せません。敵を倒すと反撃せず、勝利表示からフィールドへ戻ります。

主人公の名前・HPはコマンド窓上部の幅いっぱいの欄に表示します。名前20px・HP／MP18pxの補助数値と14px高の残量バーを使い、HP半分以下は黄、1/4以下は赤で示します。王様のセリフは頭上の吹き出しにも表示し、攻撃確定・次のコマンド・逃走・勝利で消します。吹き出しの領域を確保し、王様の姿・名前・攻撃対象のタップを遮りません。攻撃行動に任意の `speech` を設定すると、行動説明とは別に話すセリフを指定できます。

エンカウント時はゲーム枠内で一度光り、上下の黒い幕が8段階で閉じて、戦闘画面へ切り替わってから開きます。全体で約0.76秒。演出中は移動・コマンド・ターン進行を止め、再遭遇でも再生します。端末の「動きを減らす」（`prefers-reduced-motion`）では光と幕の動きを省き、約0.32秒の暗転フェードにします。非表示のタブでは演出を一時停止し、最初から・プレイ停止で解除します。演出はWeb側の共通表示で、NFC容量は増えません。

`web/src/data/encounters/enemies/` のJSONに敵ごとのHP・攻撃力・防御力・初回の反応・攻撃前／攻撃後の行動リストを保存します。王様の初期値はHP30・攻撃力6・防御力0。攻撃されるまではセリフのみ、一度でも攻撃されると「何をするんじゃ！！！」の反応を出し、杖（6ダメージ）→光（9ダメージ）を繰り返します。`player-config.json` に主人公の初期HP40・攻撃力10・防御力0と防御倍率0.5を保存します。保存後に再読み込みすると変更が反映されます。詳しくは [戦闘configの編集方法](./web/src/data/encounters/README.md) を参照してください。数値とダメージ式は試作用で、MP残量・報酬・アイテム使用・装備の補正にも対応します。特技・攻撃魔法・回復魔法のMP消費と使用にも対応します。命中・会心・属性は未実装です。

王様は撃破してフィールドへ戻るとマップから消え、同じプレイ中は再遭遇しません。別ステージへ行って戻っても消えたままで、会話・当たり判定も消えます。王様の `canEscape` を `true` に変更した場合は、逃げても王様が残り、次の成功した歩みから再び確率抽選します。再遭遇時のHPは30に戻ります。「最初から」で撃破状態を初期化します。戦闘中は歩行を止め、旧会話の決定操作で戦闘を閉じません。NFCの保存容量は増えず、見本の城と街は202Bです。

主人公の残りHPと王様を攻撃した状態は同じプレイ中に引き継ぎます。敗北後の再戦や、逃走を許可した設定で逃げて再遭遇した場合も、王様は怒ったままです。主人公HPが0になると「復活する」でHP全快、現在のマップの開始位置へ戻り、開始位置がなければ最初のマップへ戻ります。所持品・取得済み状態・撃破済み状態を保ち、王様は主人公の敗北では消えません。「最初から」／再読み込みでHP・怒りも初期化します。

玉座は絵と編集枠のサイズを保ったまま、当たり判定だけ横1マス・縦2マスにしています。左右を通れ、下側の正面から上を向いて「はなす・しらべる」で説明を表示します。城の王様が手前にいる間は王様が通行と調査を遮り、倒した後に玉座まで近づけます。

NFC向けの保存データには有効／無効・確率・敵IDを2Bで保存し、未設定ステージは1Bだけ保存します。敵名・画像・一度限りのルールはWeb共通データです。NFC実機への書き込み・URLからの起動は未接続です。


## ステータス・所持金・アイテム・装備

ゲーム中の「どうぐ」に「どうぐ・そうび・つよさ」のタブを用意しています。品名から回復アイテムを使用でき、「そうび」で武器・鎧・盾・装飾品・頭装備を着けたり外したりします。成長後の最大HP・最大MP・攻撃力・防御力に装備補正を加え、戦闘・回復・バー表示へ反映します。HP・MP・所持金は歩行画面と戦闘画面に表示します。初期所持金100Gと仮の価格・能力値を用意し、街の店員の挨拶後に買う／売る画面へ進めます。戦闘中の回復アイテムは成功したときだけ1個と1ターンを消費します。

[アイテム・装備・お店・初期値・報酬の編集方法](./web/src/data/economy.md) に追加例をまとめています。アイテムは既存ID 0〜2を維持し、装備ID 3〜8と王の装備ID 9〜12を追加しました。王冠は頭、ローブは鎧、杖と剣は武器枠で持ち替えます。王様の報酬は4点各1個・1,500G・900EXPです。プレイ状態は同じワールド内で保持し、最初から／再読み込みで戻します。Web共通定義を増やしてもNFCへはIDだけを保存するため、見本の202Bは維持します。

王様を倒してフィールドへ戻ると王冠・ローブ・剣を自動装備し、装備後の最大HP・MPまで全回復します。初期状態から倒すとHP535／MP228。王冠・ローブ・剣または杖の3点を着けている間は主人公が王様の見た目になり、どれかを外すと元に戻ります。歩く方向に合わせて正面・左右・後ろ姿を切り替え、配置サイズと足元の当たり判定は保ちます。装備中の正面は以前作った主人公ベースの王様です。左右・後ろは主人公の64×64方向素材を使い、`web/src/data/characters/king-directions.ts` で髪を銀色、青い服を赤へ置換して小さな王冠とひげを足します。元の輪郭・頭身・陰影・目・肌・ブーツを保ち、ゲーム上の描画は32×32です。素材一覧の「王様」で各方向を確認でき、`npm run export:king-pixels` で原寸PNGと拡大見本を `art/king/directions/` に出力できます。セットと自動装備の武器は `web/src/data/royal-equipment.json` で変更できます。


## HP／MPバーと特技・魔法

主人公のHPとMPは歩行・戦闘・メニューで緑／青のバーと補助の数値を表示します。戦闘の「とくぎ」「まほう」から使用できます。仮の見本として強打（MP2）、火の玉（MP3）、癒し（MP3）を用意しました。攻撃技は敵を選んでからMPを消費し、キャンセル・MP不足・HP全快の回復ではターンもMPも消費しません。技での撃破も既存の勝利・報酬・王様の消失へつながります。フィールドの「どうぐ」内の「まほう」タブでは、習得済みの回復魔法を使えます。癒しはMP3でHPを最大20回復します。HP全快・MP不足・未習得の場合は使用できず、MPを消費しません。攻撃技は戦闘中だけ使えます。

[特技・魔法の追加方法](./web/src/data/skills.md) に、共通一覧 `skill-catalog.json` と主人公の習得ID欄 `skills` の編集例をまとめています。MPは回復アイテム・復活・再遭遇へ連動します。技の共通設定を増やしてもNFCの見本は202Bを維持します。

## 経験値・レベルと習得／装備条件

敵の `reward.experience` で経験値を獲得し、`web/src/data/progression-config.json` の累計経験値表でレベルを計算します。見本はレベル10まで、1レベルにつきHP＋5・MP＋2・攻撃力＋2・防御力＋1。ゲーム内に現在レベル・経験値・次までの残量、レベルアップ後の能力増加と習得通知を表示します。魔法／特技の `learnLevel`、装備の `equipment.requiredLevel` を設定でき、従来の見本はレベル1のままです。

[成長・習得・装備制限の編集方法](./web/src/data/progression.md) に設定例と上限をまとめています。主人公の `skills` は将来習得するIDも含む一覧で、開始レベルは `initialExperience` から計算します。王様の900EXPで、初期状態のレベル1・経験値0からレベル10になります。成長状態は同じプレイ中で保持し、最初から／再読み込みで初期値に戻ります。NFC形式TQ v8・見本202Bを維持します。

## 全体マップ

紹介画面の「全体マップ」に、参考画像をもとにした海・砂浜・草原・山脈・森・川と橋の32×24マスの見本を追加しています。「歩いてみる」の「全体マップ」で試せます。エディタの「＋ 全体マップの見本」で編集中のワールドへ追加し、地形や開始位置を編集できます。海・山は通行不可、砂浜・森・橋は歩けます。街・森の入口・洞窟・魔王城を仮配置し、4種類の外観も一覧で確認できます。

場所の素材は `web/src/data/objects/world-locations.ts` の32×32ドットで、配置枠と入口は1×1マス、絵を中央に揃えて上へはみ出す形です。エディタの建物・家具で追加・移動できます。紹介画面のプレイは街・森・洞窟・魔王城へ接続し、入口の1マスへ透明な出口を重ねて移動します。魔王城の内部にも出入りできます。

「歩いてみる」で城・街・全体マップ・森・洞窟・魔王城を行き来できます。街の下端から全体マップへ出て、森の帰り道も下端にあります。エディタの「＋ 接続した冒険の見本」で、6マップを既存の編集内容へ追加できます。空いているIDへ出口も割り当て直し、「戻す」で追加だけ取り消せます。[接続・編集方法](./art/adventure/README.md) を参照してください。

森は `compiler/maps/forest.json` の19×17マスで、既存の木・苔と落ち葉の地面・曲がった土の道・広場・池を使います。広場のキラキラからやくそうを取得できます。森の出現モンスターは未指定です。モンスターの素材・ステータスはWeb側のカタログに保管し、出現する敵IDと確率はNFCに保存するステージ設定で指定します。森の全景は [森の中の見本](./art/forest/stage.png)。新しい出口は `compiler/maps/adventure-connections.json` から組み立て、元の城・街の入力を変更しません。`web/` の `npm run export:adventure` でワールドJSON・バイナリを再出力できます。接続した6マップは圧縮形式で708Bで、NFC向けの容量調整は未完了です。

## NFC容量と片手操作の改善（2026-10-12）

会話は [dialogue-templates.json](./web/src/data/dialogue-templates.json) の46種類から選ぶ方法を推奨します。既存IDは並べ替えず追加してください。IDは1B、会話だけのレコード全体は3Bです。自由文も残し、入力中にUTF-8の本文バイト数と会話部分のサイズを表示します。英数字1B・日本語3B・絵文字4Bが目安で、合成文字なども実際のサイズで数えます。

エディタの上部に「NDEF・予約領域 / タグ上限」と残容量を表示します。タグはNTAG213/215/216または手動指定。NTAG215は物理メモリ504Bに対し標準NDEF領域496Bなので、初期上限は496Bです。単一URIレコード・TLV・終端を含み、追加レコードや既存TLV等は予約欄に指定します。[NXPの仕様書](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf) に基づきます。

公開先は [TagQuest](https://tag-quest-kappa.vercel.app/)。Vercel上なら現在のorigin、ローカルならこの公開先を初期表示します。WebとPythonで `web/src/data/public-config.json` を共有し、公開先を変更する場合はここを編集します。建物を含む出力はTQ v14、建物なし・出口ありのcompact出力はTQ v13で、旧形式も読み込めます。出口は座標各5bit・方角2bit・移動先のワールド内番号を連続して保存し、床は重ね塗りを維持したまま隣接RECTと横・縦走査を比較します。編集JSONを変更せず出力を最適化します。

スマホ幅ではメニューを下寄せにし、4つのタブを並べ、44px以上のタッチ領域を維持します。左右キーのタブ移動・Escで閉じる・空スキル一覧から戻る・逃走不可ボスのターン非消費・仮想パッドの長押しとポインターキャプチャは維持し、既存の操作検証を通しています。実スマホの画面・タッチ感は未確認です。

`npm run verify:nfc` はWeb/Python59往復、最大255マップ/255出口、旧IDと前方参照、重ね塗り、UTF-8、NDEF長さ境界、Vercel URL復元と移動を検証します。`npm run verify:all`にも含めています。容量の結果と次の案は [NFC最適化の記録](./docs/nfc-optimization-2026-10-12.md) を参照してください。

## NTAG215へ収まる固定見本
