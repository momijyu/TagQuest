# NFC RPG Compiler（容量検証用）

城と街の現在の見本を、小さなバイナリに変換するPythonコンパイラです。
外部Pythonパッケージは不要です。最終仕様ではなく、[project.md](../project.md) の容量検証の試作です。

リポジトリ直下で実行：

```sh
python3 compiler/build.py
```

入力は `maps/castle.json` と `maps/town.json`。床の長方形・種類名・座標を編集できます。
種類IDは `web/src/data/scene-catalog.json` をTypeScriptと共有します。
出力は `web/src/data/generated/` の `scenes.bin`・`scenes.report.json`・`scenes.url.txt`。
生成したバイナリをWeb側で読み込み、現在の城と街を復元して表示します。

`web/` の `npm run dev` と `npm run build` の開始時にも自動生成します。
サーバー起動中にマップを編集した場合は `web/` で `npm run compile:maps` を実行してください。

URLの長さを本番用のアドレスで計測する場合：

```sh
python3 compiler/build.py --base-url https://your-domain.example/g
```

生成URLを開いてゲームを起動できます。NFCへの書き込みは外部アプリで行います。レポートはURL長に加え、単一NDEF URIレコード・TLV・終端を含む使用量と496Bに対する残量を表示します。実タグは未検証です。

現在の結果はTQ v14で、城49B・街149B・共通ヘッダー4B、合計202B（会話テンプレート7人・キラキラの中身2件・出口2件・城のエンカウント設定を含む）。`--compact` は195Bです。
床のRAW・RLE・RECTを比較し、最小の方式を選択します。詳細は [FORMAT.md](./FORMAT.md)。

検証コマンド（Webの依存関係は先に `web/` で `npm ci`）：

```sh
python3 -m unittest discover -s compiler -p 'test_*.py' -v
node compiler/verify.mjs
```

前者はPython側の入力と容量、後者はPython→TypeScriptの往復と不正なバイナリの拒否を確認します。

建物は中央の横2マスを設置・通行判定に使い、元の絵を左右にはみ出して描きます。新しいJSONは `buildingAnchor: "frame"` で枠の左上を保存します。識別値のない旧JSONは絵の左上から自動変換します。絵のサイズと縦の配置サイズはWeb共通定義で保持し、NFCへ追加パラメーターを保存しません。建物ありの出力はv14、旧バイナリも読み込めます。

## エディタからの入力

`http://localhost:5173/#editor` でマップを編集し、マップJSON・ワールドJSONを書き出せます。
`--maps` は単体マップ、マップの配列、`stages` を持つワールドJSONを受け付けます。

```sh
python3 compiler/build.py --maps /path/to/tagquest-world.json --compact --out /tmp/tagquest-world.bin
```

エディタが出力するバイナリと同じ内容を生成します。
編集用JSONの長方形指定は4096個まで、RECTバイナリは255個までです。RECTで表せない場合はRAW・RLEから選びます。
エディタは同じ床をまとめて指定数を減らしますが、最適な長方形分割を保証するものではありません。
Web側の編集・書き出しの検証は `web/` で `npm run verify:editor`。

標準出力は床とイベントに応じてTQ v8〜v10、`--compact` を付けるとエディタと同じTQ v11です。主人公の開始座標は横1×縦2マスの配置枠の左上です。
JSONに `spawnAnchor: "frame"` を付けます。従来のJSON（この項目なし）は絵の左上として読み込み、Xへ8px足して変換します。絵の32×32px表示を維持します。
全NPC（王様・店員3人・住民3人）は横1×縦2マスの配置枠の左上を保存し、JSONには `npcAnchor: "frame"` を付けます。省略した旧JSONでは王様・店員のXへ8px足して変換します。住民は旧識別値 `residentAnchor: "frame"` があれば変換済みとして扱い、両方の識別値がなければ同じくXへ8px足します。絵の位置を維持し、再保存で二重変換を防ぎます。他のオブジェクトの座標基準は変更しません。

## 会話とアイテム指定

NPCにテンプレートまたは自由文、キラキラにWeb共通一覧のアイテムIDを指定します。以下は各配置レコードへの追加項目です。

v8では玉座・柱・井戸・城・店・民家にも `dialogue` と `itemId` を設定できます。調べるとメッセージ→入手表示を出し、取得後もオブジェクトを残します。アイテムは1プレイ中に1回だけで、再訪でも取得済み状態を保ちます。対象一覧は `web/src/data/inspectable-objects.json` です。両方を指定するモード3／4も保存・容量計算へ含め、旧v1〜v7も従来の指定ルールで読み込めます。標準の城＋街は202B。充実版の冒険見本ではオブジェクトにも会話とアイテムを指定します。

```json
{"dialogue": {"type": "template", "id": 0}}
{"dialogue": {"type": "custom", "text": "ようこそ！\nよい旅を。"}}
{"itemId": 0}
```

会話テンプレートは `web/src/data/dialogue-templates.json`、アイテム一覧は `web/src/data/item-catalog.json`。仮のアイテムは0＝やくそう、1＝どくけしそう、2＝まほうの水です。使用効果・価格・装備は同じ一覧に設定します。ID 3〜8の装備も追加し、品名・価格・能力値はNFCへ重複保存しません。自由文はUTF-8で1024B以内で、本文の長さがそのまま容量へ加わります。未指定なら会話・取得は発生しません。

エディタでは配置したNPC／キラキラを選び、会話／アイテムを指定して「配置を反映」を押します。JSON・バイナリ・ブラウザ保存・取り消し履歴に含まれ、紹介画面とエディタのプレイで同じ処理を使います。既存のブラウザ保存に設定がなければ、自動で見本の内容を上書きせず未設定のまま読み込みます。

操作はE・Enter・Spaceまたは「はなす・しらべる」。キラキラは触れても取得し、取得後はそのプレイ中だけ消えます。「最初から」で所持品と取得状態をリセットします。購入・売却・使用・装備に対応します。プレイ結果の永続セーブは未実装です。

`web/` の `npm run verify:interactions` で設定の往復・Pythonとの一致・容量報告・不正入力・会話・取得を検証します。

## 出口でのステージ移動

マップの `exits` 配列へ出口を記述します。床や配置物の見た目はそのままで、足元がこのマスへ入ると移動します。

```json
{"exits": [{"x": 3, "y": 5, "targetStageId": 1, "targetX": 6, "targetY": 7, "direction": "front"}]}
```

座標はすべて0始まりのマス。`targetX`／`targetY` は到着する主人公の足元で、向きは `front`（下）・`back`（上）・`left`・`right` です。到着先の開始位置とは独立しています。1件6Bと各マップの件数1Bを保存し、v1〜v5も出口なしとして読み込めます。

接続先があるマップはワールドJSONか、接続に必要な全マップを `--maps` に渡してください。単体マップだけでは存在しない移動先を参照できません。出口・到着位置の通行可否はプレイ開始時に検証します。

エディタの「出口」でマップをタップし、移動先・到着する足元の列と行・向きを設定します。画面上の列と行は1始まりです。往復にはそれぞれ出口を置きます。マップ削除時はそこへ向かう出口も削除し、縮小時は範囲外になる出口・到着先を削除します。「戻す」で復元できます。旧ブラウザ保存は自動で書き換えず、出口なしなら手動で追加します。

`web/` の `npm run verify:world` で実際の城・街の往復、取得状態の保持、到着直後の再発動防止、Pythonとの一致、不正な接続を検証します。

## 歩行中の確率エンカウント

マップごとに次の設定を保存します。敵ID 0はWeb共通の王様です。

```json
{"encounter": {"enabled": true, "enemyId": 0, "rate": 10}}
```

`rate` は1歩ごとの0〜100%（整数）。未設定は抽選なしの1B、設定済みは2Bです。無効にしても選んだ敵と確率は保持します。旧v1〜v6と設定のないJSONは抽選なしで読み込みます。旧王様レコードの引数は互換性のため残し、新しい抽選はマップの `encounter` で制御します。

エディタの「エンカウント」で敵・有効／無効・確率を選び、「エンカウントを反映」で保存します。見本の城は仮に10%、街は未設定です。移動に成功した歩みだけ抽選し、出口ではステージ移動を優先します。キラキラと重なる場合は取得メッセージの後に遭遇を表示します。

王様は戦闘に勝利した場合だけマップの表示・会話・当たり判定から消え、撃破後は同じプレイ中のステージ再訪でも再出現しません。逃走時は残り、再遭遇できます。「最初から」で復元します。Web側のJSONで敵HP・攻撃力・防御力・攻撃前後のセリフと行動パターン、主人公の能力値と防御倍率を編集できます。敵ターン・防御・勝利・逃走・敗北と復活を実装し、数値とダメージ式は試作用、報酬は敵一覧JSONの `reward` から勝利時だけ付与します。王様の報酬は1,500G・900EXP・王の装備4点です。詳しくは `web/src/data/encounters/README.md` を参照してください。玉座の判定は中央1×2マスとし、正面から調べられます。戦闘の素材・数値・当たり判定はWeb共通定義で、現在の標準見本はTQ v14・202B、compactは195Bです。

`web/` の `npm run verify:encounters` で確率の境界・移動時だけの抽選・王様の消失と再訪・リセット・取得との順序・保存形式を検証します。`verify:editor` はエディタ設定・タッチボタン・所持品／会話中の停止、戦闘画面への切替・コマンドと敵選択・逃走後の復帰も検証します。

## 壁の向きの自動描画

城は `wall-top`、魔王城は `demon-wall-top` の1種類で壁を保存します。旧左右・角の名前は `web/src/data/wall-families.json` に従って統合し、WebのエンコーダーとPythonは同じIDを出力します。旧IDは読み込み互換用にカタログに残します。描画時は周囲の壁・床から向きを選び、向きのレコードは保存しません。旧マップの床・壁の位置や配置・会話・出口の情報は維持します。不要な角の指定を削除した当時は城・街206B・6マップ954Bでした。現行の城＋街は通常202B・compact195B、充実した6マップのcompactは742Bです。

全検証とビルドをまとめて実行する場合は、`web/` で `npm run verify:all`。ボスの指定とv11の詳細は [FORMAT.md](./FORMAT.md) を参照してください。

充実版の冒険は別の `maps/adventure-castle.json`（13×12）と `maps/adventure-town.json`（25×21）を使います。`web/` の `npm run export:adventure` で6マップを `art/adventure/` へ出力します。標準の小型城＋街の容量検証と区別します。

公開先の初期値は `web/src/data/public-config.json` の `https://tag-quest-kappa.vercel.app/` をWebと共有します。`--base-url` で個別に上書きできます。小型城＋街のcompactは195B・URL296B・NDEF301Bです。
