# 全体点検後の改善記録

[点検報告](./audit-2026-10-11.md) のA1〜A5と、制作・NFC起動・ボス進行・描画の改善を実装した。Gitの操作は行っていない。

## 不具合修正

- **A1 保存**：変更候補を正規化し、バイナリ化まで確認してから履歴・localStorageへ反映する。ペン・四角塗り・フォーム・JSON読み込みを同じ経路で扱う。容量制限の超過は保存・履歴を変更せず復元する。起動時に読み込めないデータは `.recovery` へ退避し、`.last-good` または初期の城・街を開く。「退避データ」で元のJSONを書き出せる。最後の正常データは編集マップ用で、プレイ状態のセーブではない。
- **A2 帰還**：敗北時に現在の開始位置の足元を調べ、使えない／未設定なら最初のマップの開始位置へ帰る。帰還先を確定してから戦闘結果を反映する。エディタの検証でも危険な開始位置を表示する。
- **A3 配置**：`entity-frames.json` をPythonとWebで共有し、JSON・現行バイナリで配置枠が収まるか検証する。NPC・入口の絵のはみ出しは許容する。縮小時は枠が収まらなくなる配置を削除し、事前確認と履歴で復元できる。
- **A4 敵**：通常のランダム敵は新しい個体として未攻撃状態から始める。王様の既存の怒りと、新しいNPC戦闘イベントの挑発状態は、対象を特定してプレイ中に保持する。
- **A5 画像**：参考PNGがある敵だけ読み込む。魔王のコード製ドット素材と参考画像の有無を分離する。

## エディタとNFC URL

「NFC用URL・マップ検証」から公開先・NDEF領域・予約容量を指定する。URLを書き出し、「このブラウザで試す」で同じバイナリをURLから読み込める。公開URLは実際のホスティング先に変更する。ゲームはワールド内で最初に開始位置があるマップから始まる。

`#Base64url` と `#game=Base64url` を復号し、v1〜v11に対応する。`#editor` と紹介画面のアンカーは維持する。壊れた／未知バージョン／開始位置なしのデータには、エラーと戻るリンクを表示する。エディタは必要時の動的読み込みに分けた。

マップ検証は開始位置、出口と到着先、到達範囲、NPCの未設定、配置・保存の制限を確認する。結果のボタンで該当マップ・位置へ移動する。到達範囲の計算は移動途中の1pxごとの通行判定も使う。NPCについては近づける位置の確認で、特殊な会話イベントの意図を判定するものではない。

当たり判定表示は青が配置枠、赤が通行不可の枠。「移動」ツールでは地形を変更せずマップ内をスクロールできる。個別マップ削除と縮小にも確認を入れ、戻す／やり直すを保つ。装備の購入・選択時に最大HP・MP・攻撃・防御の変化を、装備済みの品と能力上限を含めて表示する。スマホの編集ボタンは44px以上にした。

## 保存構造と容量

山41個・森46個を全体マップの床ID 25・26へ変換した。以前の素材を床に合成しており、全マップの画素と通行判定が旧配置方式と一致することを検証した。旧配置ID 20・21も読める。「山・森の配置を床にまとめる」は、既存の編集データについて、グリッド・下地・追加イベントが安全に変換できるものだけを対象にする。

v11は配置枠が16pxグリッドに一致するステージの配置を、種類6bit＋X5bit＋Y5bitの2Bにする。引数は従来どおり。2px配置があるステージは従来形式を保つ。JSONと画像・判定の位置を変更せず、PythonとWebのバイト列一致を確認する。

| 対象 | バイナリ | URL全体 | NDEF/TLV込み |
|---|---:|---:|---:|
| 城・街の標準v8 | 206B | 297B | 302B |
| 城・街のエディタv11 | 204B | 294B | 299B |
| 6マップ：床化のみ | 724B | 988B | 993B |
| 6マップ：床化＋v11 | 699B | 954B | 959B |

公開先は `https://example.com/g`。6マップは変更前954Bから699Bへ255B減った。v11の空イベント件数も含む。新しいボスイベントを1個入れると、さらに3BとURLの増分が必要になる。ゲーム固有の配置・接続をWebの固定マップへ移して容量を合わせる変更は行っていない。

単一URIレコードの接頭辞省略、短／長レコード、TLVの長さ、終端を計算する。タグ容量の既定は496B。6マップの959Bはまだ463B超過し、NTAG215へ収まらない。追加の汎用圧縮は小さい城・街に逆効果だった点検結果から、常時適用はしていない。さらに構造を圧縮するか、実際に保存するマップの規模・タグ容量を決める必要がある。書込アプリの追加レコードや実CCは別途確認する。

## ボスと描画

NPCを選び、敵ID・勝利時の消失・クリアをNFCの配置設定として指定する。会話を閉じて戦闘へ入り、逃走・敗北なら再挑戦できる。勝利時だけ指定したNPCを消し、クリア指定ならGAME CLEARを表示する。対象ごとの状態はマップ再訪でも保ち、最初からで解除する。見本に敵・魔王を自動配置していない。

魔王のHPは武器・装備を追加してから調整するというユーザー指示に従い、HP120・攻撃12・防御4、剣power 1／炎power 1.4へ戻した。王の装備の大幅な能力上昇は維持する。`royalEquipmentAttack` で王の装備に対する攻撃力100倍を設定し、ユーザー指定の現在の条件はany（1点以上）。configでset（王様の見た目になる3点）へも変更できる。判定は戦闘開始時の装備に基づき、所持だけでは発動しない。倍率は敵の基礎攻撃力へ適用してから、攻撃のpower・防御力・ぼうぎょを計算する。他の敵は倍率を未設定なら通常どおり。報酬は0G・0EXP・アイテムなしを保持する。装備解除して再戦すると通常攻撃力へ戻ること、個別の4装備・完全セット・通常の装備・所持だけのケースを検証する。

コードのピクセルをOffscreenCanvasへ一度描いて再利用し、地形も背景としてキャッシュする。木・NPC・宝箱は従来の奥行き順で重ねる。非対応環境は元の描画処理で動く。戦闘／メニュー中はキラキラによる不要な地図更新を止めた。キャッシュあり／なしの画素一致と、2回目に地形・素材を再描画しないことを模擬Canvasで確認した。実機FPS・電池消費の改善率は未計測。

`web/` で `npm run verify:all` により、Web11本、フォントの復元確認、Python13テスト、Python→Web17往復、型チェック・ビルドをまとめて実行する。保存失敗・復旧、移動後の敗北、配置枠、個体の状態、参考画像、NDEF境界、v10/v11往復、NPCイベントとクリア・リセット、王の装備による条件付き攻撃力倍率、地形変換・キャッシュの画素一致を確認した。模擬DOMでもエディタのボス設定→会話→戦闘→クリア表示を確認した。全検証は成功した。

## 追加のconfig整理・デバフ・読み込み改善

- 敵configをencounters/enemies/のJSONへ分け、enemy-catalog.jsonを共通の登録一覧とした。WebとPythonは同じ一覧を読む。[設定の編集場所](../web/src/data/README.md) に魔王・王様・主人公・成長・装備・技・店・会話をまとめた。
- 魔王戦でroyalEquipmentPlayerAttackMultiplierを0にし、王の装備の攻撃ボーナスだけを無効化する。基礎能力・通常装備・HP/MP/防御・固定ダメージ魔法は保つ。Lv10の通常攻撃24、強打38ダメージ。戦闘終了後に通常性能へ戻す。魔王の攻撃100倍条件は維持する。
- 以前はどのURLでも紹介画面の見本マップを取得・描画してからルーティングした。main.tsをルーティングに絞り、紹介画面の初期化をgallery.tsへ移した。URLゲーム・エディタを開くだけなら紹介の初期化や専用マップ取得を行わない。壊れたURLは画像読込前にエラーを表示する。紹介マップの取得失敗がURLゲームを止めない。
- 非同期読込中にページを変えた場合、古いゲームやエディタを起動しない。紹介／エディタは再訪で二重に初期化せず、終了時・失敗時はアニメーションや入力イベントを解除する。非表示の紹介のキラキラは再描画しない。実HTMLの素材一覧・キャンバスを使った模擬描画と、画面切替のキャンセル・失敗・再訪・破棄をverify-routingで確認した。
- 完全なPixelMplus12をWOFF 1.0で保存する。1,274,396→409,752B（67.8%削減）、7,253グリフ・cmapなど全テーブルを保持。原TTF・ライセンスは維持し、CSSはWOFFを優先してTTFを互換用に残す。Python標準ライブラリだけで生成でき、復元TTFが原本と全バイト一致することを検証する。[圧縮仕様](https://www.w3.org/TR/WOFF/) を参照。
- NFC用ゲーム画面はsvhとノッチの余白を使い、画面高さに合わせて地図／操作・戦闘を配置する。横画面の戦闘メニューは高さを制限してスクロールできる。小さい縦画面はHP/MPを横並びにし、長い敵名・アイテム名を折り返す。実端末での見た目は未確認。
- ビルドの初期JSは約12.58kBで、前回の約26.67kBから分割した。ゲーム・共通設定・画像等の追加チャンクは必要時に読む。数字はビルド出力であり、実際の通信速度・FPSを測ったものではない。
- READMEのURL未対応・井戸未対応・セーブ追加予定という古い説明も現在の仕様へ揃えた。全検証と型チェック・ビルドが成功した。
